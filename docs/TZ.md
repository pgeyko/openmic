# OpenMic — ТЗ (смартфон как микрофон для Linux по Wi-Fi)

## 1. Цель
Превратить Android-смартфон в беспроводной микрофон для Linux (цель — ALT Linux p11):
говорим в телефон → звук идёт по Wi-Fi на ПК → приложения (браузер, Zoom, Telegram, OBS)
видят источник «OpenMic» как обычный микрофон.

Без видео, без ядра/модулей, без root.

## 2. Объём (что делаем / не делаем)

**Делаем:**
- Android-приложение: захват микрофона, отправка по Wi-Fi, самоконтроль в наушники, график голоса, настройки.
- Десктоп-демон + CLI: приём звука, виртуальный микрофон PipeWire, настройки, автопереподключение.
- Сопряжение по QR (IP + порт + токен) и вручную.

**Не делаем (вне объёма v1):**
- Видео/камеру, v4l2loopback.
- Opus-кодек (только если PCM не хватит) — v1 гонит сырой PCM.
- mDNS-автодискавери, Bluetooth-транспорт, шифрование трафика.

## 3. Роли и сценарии

1. **Докладчик:** кладёт телефон рядом, говорит, слушает себя в наушниках (режим отладки), смотрит уровень на графике.
2. **Слушатель на ПК:** выбирает «OpenMic» в Zoom/Chrome, слышит голос без лишних действий.

Базовый флоу: открыть приложение → нажать «Старт» → отсканировать QR в десктоп-клиенте (или ввести IP) → говорить. Обрыв Wi-Fi → автопереподключение + заглушка (тишина) на виртуальном микрофоне, без пропадания устройства из системы.

## 4. Функциональные требования

### 4.1 Android-приложение (Kotlin)
- **Захват:** `AudioRecord`, 48 кГц / 16 бит / моно. Источник на выбор: `VOICE_RECOGNITION` (по умолчанию), `UNPROCESSED`, `CAMCORDER`, `VOICE_COMMUNICATION`.
- **Фон:** foreground-сервис типа `microphone` + `PARTIAL_WAKE_LOCK`. Работает с заблокированным экраном. Настройка «не гасить экран» (`FLAG_KEEP_SCREEN_ON`) как опция, а не требование.
- **Самоконтроль (режим отладки):** дубль захваченного голоса в подключённые наушники через `AudioTrack` (`PERFORMANCE_MODE_LOW_LATENCY`). Отдельные тумблер и ползунок громкости. Предупреждение в UI: «по Bluetooth задержка 150–300 мс — это нормально».
- **График голоса:** RMS за 20–50 мс, полоса-индикатор + волна, клиппинг-индикатор (красный при перегрузке).
- **Настройки микрофона:** источник, частота (16 / 44.1 / 48 кГц), усиление 0–200%, шумодав и эхоподавление (вкл/выкл, если поддерживаются), кнопка «исключить из оптимизации батареи» с диплинком в настройки.
- **Сопряжение:** экран «Старт/Стоп», QR-сканер (ZXing, без сервисов Google):
  IP + порт + токен подставляются из QR десктопа автоматически; ручной ввод
  как запасной. Статус подключения с точкой-индикатором, пульсация при
  переподключении, спиннер, волна уровня с клиппингом.
- **Тема:** системная DayNight (тёмная ночью).
- **Без Google-сервисов и проприетарных SDK.**

### 4.2 Десктоп (Rust: демон `openmicd` + CLI `openmic`)
- **Виртуальный микрофон:** модуль PipeWire `module-pipe-source` с именем `OpenMic`
  (`s16le 48кГц моно` — ровно формат телефона, без ресемплинга). Демон держит FIFO
  `$XDG_RUNTIME_DIR/openmic.pipe` открытым и качает туда PCM; без телефона льёт
  нули. Модуль живёт независимо от демона — устройство существует всегда, даже
  без телефона (в тишине отдаёт нули). Нативный `pipewire-rs` не используется:
  ему нужен libclang для bindgen, а `aplay`/`ffmpeg` игнорируют выбор sink
  (проверено). `monitor`-источники не используются — их скрывает Chrome.
- **Приём:** одно TCP-соединение, переподключение с backoff 1→2→5→10 с.
- **Настройки:** усиление 0–200% и Mute на стороне демона (применяются к PCM до
  FIFO; control-сокет `$XDG_RUNTIME_DIR/openmic.sock`), выбор сети/порта,
  список доверенных телефонов (по токену), автозапуск user-юнита systemd.
- **CLI:** `openmic connect <ip> | qr` (пока только `status` с qr-json),
  `openmic mute|unmute`, `openmic gain <0-200>`, `openmic status` (токен + qr-json
  + состояние демона), `openmic doctor`, `openmic tonesend` (тест без телефона).
- **GUI нет в v1** (только CLI + `pavucontrol` для проверки).

## 5. Протокол (v1, заморозка)

Одно TCP-соединение. Всё маленькое-endian.

1. Handshake (JSON строкой с `\n`):
   - `C→S: {"hello":"openmic/1","token":"<64-hex>"}`.
   - `S→C: {"ok":true,"sampleRate":48000,"channels":1} | {"ok":false,"error":"bad-token"}`.
   При `bad-token` — разрыв, телефон показывает «отклоните/подтвердите ПК».
2. Управление (JSON строкой с `\n`, в любую сторону):
   `{"type":"gain","value":120}`, `{"type":"mute","value":true}`, `{"type":"ping"} → {"type":"pong"}`.
3. Аудио (бинарные фреймы): `[u32 len][i16 PCM …]`, `len` — байты PCM, один фрейм = 20 мс (960 сэмплов при 48 кГц = 1920 байт).
4. Десктоп→телефон (S→C, тем же соединением, после welcome): JSON-строки
   `{"type":"ns","value":bool,"seq":N}` — шумодав и будущие параметры. Телефон
   читает их фоновым тредом (один на соединение). Демон хранит желаемое
   состояние и рассылает новым клиентам при коннекте + живым через broadcast.
5. Токен: 128 бит, генерируется демоном при первом старте (`~/.config/openmic/token`),
   передаётся через QR/ручной ввод. Перевыпуск — удалением файла + рестарт.
6. Локальный control-сокет демона (`$XDG_RUNTIME_DIR/openmic.sock`): `{"gain"}`,
   `{"mute"}`, `{"ns"}` (на телефон), `{"status"}`, `{"watch":true}` (стрим
   уровня 10 Гц для GUI).
7. Порт по умолчанию: `59100`.

Почему не RTSP: для одного микрофона не нужна A/V-синхронизация, PCM по TCP даёт меньше задержки и кода.

## 6. Нефункциональные требования (критерии приёмки)

| Метрика | Цель | Как меряем |
|---|---|---|
| Задержка Wi-Fi (щелчок → `pavucontrol`) | < 150 мс медиана | тест щелчком + замер в демоне (`--measure`) |
| Демон в простое | RSS < 25 МБ, CPU ~0% | `systemd-cgtop`, `ps` |
| Телефон, 1 час эфира | без троттлинга, −15–25% батареи | `dumpsys battery`, субъективно нагрев |
| Обрыв Wi-Fi 10 с | устройство не пропадает, звук возобновляется сам | ручной тест + лог |
| Chrome / Firefox / Zoom / Telegram | «OpenMic» виден и пишет | ручная матрица (headless-`enumerateDevices` в этом окружении виснет без X, Xvfb нет — только живой браузер) |

## 7. Безопасность
- Шифрования нет (доверенная LAN, как в исходном плане).
- Авторизация обязательна: токен 128 бит, подтверждение нового ПК на телефоне, список доверенных, отзыв кнопкой.
- Предупреждение об открытой Wi-Fi без пароля → предлагать домашнюю сеть/USB-модем.

## 8. Установка (ALT p11)
- Android: APK, собирается локально (`env.sh` + `./gradlew assembleDebug`). Разрешения запрашиваются при первом старте.
- Linux: `cargo build --release`, бинарь `openmicd` + user-unit systemd. Никаких модулей ядра, `sudo` нужен только для установки бинаря/юнита. `openmic doctor` проверяет PipeWire, сеть, права.
- Окружение сборки уже изолировано в репо: `.jdk/`, `.android-sdk/`, `env.sh` (удаление = `rm -rf`).

## 9. Тестирование
- **M0 (прототип):** Python-приёмник PCM → `pw-loopback`/remap-хак → слышно в `pavucontrol`. Критерий: голос идёт, задержка глазом < 0.5 с.
- **M1:** нативный виртуальный микрофон, FGS с заблокированным экраном 30 мин на Realme 9 Pro+ (A14) + Redmi 9 (A11/MIUI), матрица Chrome/Firefox/Zoom/Telegram, тест обрыва.
- Автотест браузера: Chromium `--use-fake-ui-for-media-stream`, `getUserMedia({audio})` → метка «OpenMic», RMS кадра > 0.

## 10. Вехи
- **M0 — 2–3 дня:** PCM по TCP слышно на ПК любым костылём.
- **M1 — 2–3 недели:** приложение + демон + QR/токен + самоконтроль + график + `doctor`. Приёмка по §6.

## 11. Открытые риски
1. OEM (Realme UI/MIUI) убивают FGS → митигация: исключение из оптимизации + тесты на двух живых телефонах.
2. BT-наушники дают большую задержку самоконтроля → не фиксится, только честное предупреждение.
3. Шумодав разных вендоров красит звук → настройка источника + вкл/выкл NS.
